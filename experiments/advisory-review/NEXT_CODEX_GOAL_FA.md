# Goal — P0-03 Local Pilot Qualification and Controlled First Paid Batch

در این Goal فقط بستهٔ مستقل `projectctl_parallel_phase2_2026-10-18` را بررسی کن. **هیچ فایل داخل ریپازیتوری اصلی ProjectCTL، ADR، State، Blueprint، Verification Catalog یا M6.0 را تغییر نده.** این Goal برای اجرای در محیط مالک است؛ هزینهٔ مدل یا نصب ابزار فقط بعد از تأیید صریح مالک مجاز است.

هدف: اعتبارسنجی فنی Runner، جداسازی واقعی داده‌های داور از Reviewer، سازگاری Flagهای Codex CLI نصب‌شده و سپس (تنها با اجازهٔ جداگانهٔ مالک) اجرای نخستین Batch سه‌تایی واقعی با مدل و Reasoning ثابت. از بازنویسی Frameworkها یا تغییر Scope به پروژهٔ اصلی خودداری کن.

مراحل در یک Goal منسجم:

1. ساختار بسته، `OWNER_RUN_GUIDE_FA.md`، پروتکل قبلی `source_bundle/EVALUATION_PROTOCOL_FA.md` و threat model را بخوان؛ SHA فایل‌ها و تمیزی بسته را ثبت کن.
2. آزمون‌های قدیمی Fixture و هفت آزمون جدید Runner را اجرا کن. ناسازگاری‌ها و نقص‌های واقعی با اصلاحات محدود **فقط داخل این بسته** رفع شوند.
3. در یک مسیر تازه ۹ Prompt کور بساز؛ بررسی کن هیچ oracle/gold و کلید پاسخ در Prompt، CWD، mountهای قابل مشاهده یا آرگومان‌های مدل قرار نگرفته باشد. اگر OS Isolation از نگاه Reviewer برقرار نیست آن را **عدم اثبات** ثبت کن، نه موفقیت.
4. با `codex exec --help` و `codex --version` سازگاری `--ignore-user-config`, `--ephemeral`, `--sandbox read-only`, `--json`, `--output-schema`, `--output-last-message` را بررسی کن؛ بدون شروع Turn پولی. دربارهٔ احتمال آلودگی Context از طریق تنظیمات و Skillهای سراسری شفاف باش.
5. پیش از هر اجرای پولی، وضعیت Quota و سقف‌های کاربر را بازبینی کن؛ مدل و Budget را با مالک هماهنگ کن. بدون مجوز صریح هزینه، **در نقطهٔ آمادگی متوقف شو** و فقط دستور دقیق Batch اول را ارائه بده.
6. پس از مجوز، فقط سه Run مربوط به case-01 را اجرا کن. برای هر کدام شناسهٔ اجرا، Digest ورودی، متن خروجی، Schema validation، خطاها، رویدادهای Tool، توکن‌های گزارش‌شده و زمان واقعی را ثبت کن. هر Tool call غیرمنتظره یا خطای Schema باید Batch را متوقف کند.
7. نتیجه را به‌صورت `PASS/FAIL/BLOCKED` گزارش کن و مرز یافته‌های Mock، مدل واقعی و Gold Adjudication را حفظ کن. هنوز دربارهٔ برتری بازوها نتیجهٔ معماری نگیر. هیچ PR یا Commit در پروژهٔ اصلی نساز.

تعریف Done: آزمون‌های بسته سبز؛ پیش‌نیازها روشن؛ اولین Batch واقعی با اجازهٔ مالک انجام شده یا با دلیل دقیق در نقطهٔ بدون‌هزینه BLOCKED است؛ فایل‌های خروجی و مسیر ادامه مشخص‌اند.
