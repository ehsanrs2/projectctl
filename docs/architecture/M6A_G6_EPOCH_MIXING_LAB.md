# M6a G6 — Synthetic DB/JSON epoch-mixing negative controls

**Scope:** Issue #149, LAB_ONLY, read-only Trace research; no production source acquisition.
**Base:** `main@59cf22ae8b9d327478accae3f5214d141d372062` (merged #148).
**Implementation:** `tests/test_m60m6a_g6_epoch_mixing.py`; no runtime or schema change.

## Falsifiable question

Does the private G5 → G4 → G3 → G2 pipeline authenticate that separately
obtained SQLite and context JSON bytes belong to one committed epoch?
**No such guarantee is implemented.** G2 checks structure and available
task/run identity, not a producer-authored cross-store epoch. G4 explicitly
emits `cross_store_epoch=UNATTESTED`, `source_current=UNKNOWN`, and empty
assessments. The experiments below exercise the actual pipeline and use a
**test-only external fixture oracle**. The test oracle labels A/B but does
not pass its labels to the pipeline.

## Test design and expected truth table

| Scenario | Fixture-generation oracle | Expected G5/G4 observation | Correct scientific interpretation |
| --- | --- | --- | --- |
| DB A + context A | Co-generated pair A | Well-formed input, context present, incomplete, UNATTESTED | Consistency known only to test fixture, not proven by consumer |
| DB B + context B | Co-generated pair B | As above | Same caveat |
| DB A + context B | Deliberately mixed | Well-formed input, same task, context present, incomplete, UNATTESTED | Mixed epoch is not established by G2's identity checks |
| DB B + context A | Deliberately mixed | As above | Same limitation |
| Old wire, named context replaced after capture | Source now differs | Old wire is deterministically renderable, source_current UNKNOWN | Historical supplied bytes must never be represented as current |
| DB B published while context A remains | Publication interrupted | Same truthful incomplete/unattested output | Observational reads cannot certify transactionally coherent pair |
| Then context B published | Co-generated pair B | Still UNATTESTED | A coherent pair is not proof that producer authenticated its epoch |

The B SQLite image is generated by a committed update of an event type on
the existing synthetic rollback-mode fixture. B context has a different valid
`git_commit` and the same `task_id`. This deliberately tests the gap
between **schema identity validation** and **independent epoch provenance**.
No real project database, live WAL or producer is read.

Expected test commands on an ordinary non-root Linux account:

```sh
python -m pytest -o addopts='' -q -rs tests/test_m60m6a_g6_epoch_mixing.py
python -m pytest -o addopts='' -q -rs tests/test_m60m6a_g*.py
```

These are **expected assertions, not observed passing results** until an
exact-head CI or non-root environment executes them.

## Hypothesis comparison (not implementation permission)

1. **Observation-only G5 double metadata check:** detects persistent
   identity/metadata differences within the sampled interval. It cannot prove
   cross-store publication epoch, detect every same-UID adversarial ABA, nor
   authenticate which writer produced the files. Correct outcome: L0/L1 only.
2. **Future fenced producer epoch with immutable retained bytes:** *may* bind
   DB status/event boundary and exact artifact versions if the producer and
   commit/custody protocol are independently trustworthy and crash-safe.
   Existing W1c disposable test is not such a real producer. Requires distinct
   Writer and Reader gates from
   `M6_0_B2B_SNAPSHOT_CONSISTENCY_REVIEW.md`; remains a hypothesis.

## Known gaps and stop conditions

- No proof that unobserved ABA, transient WAL/sidecars, checkpoint cycling,
  ancestor symlink/mount aliases or hostile concurrency are prevented.
- No atomic source snapshot, immutable file retention, non-mutating live-WAL
  reader, independent issuer/custody, current status or external provider proof.
- G5's bounded byte lengths do not imply measured hard peak RSS/CPU bounds.
- No new authority or even a result stronger than `UNATTESTED` is permitted.
- `M6b P0–P4=NO_GO`; `R0b=C_FAIL_CLOSED` remain unchanged.

Existing detailed writer ordering and fault matrix live in
`docs/architecture/M6_0_B2B_SNAPSHOT_CONSISTENCY_REVIEW.md`.
Issue #124 controls unresolved owner trust/topology decisions. This short
report intentionally does not establish a second architecture decision.
